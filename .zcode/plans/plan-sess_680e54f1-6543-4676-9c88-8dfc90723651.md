## Goal
POS receipt customization (QR toggle, merchant number, 3 top text lines) + POS orders become silent (no notification) and auto-complete to `completed` the moment Pay is clicked. **Online web-checkout is unchanged.**

All new settings live in Settings → Point of Sale (localStorage, matching the existing pattern) and are applied only on the POS receipt path.

## Part A — New POS receipt settings (Settings → Point of Sale)

Extend the settings object (`SettingsView.tsx` `DEFAULTS`, `PosView.tsx` `readPosSettings`, `lib/receiptSettings.ts`) with:
- `receiptQr: boolean` (default `true`) — show/hide the QR on POS receipts
- `merchantNumber: string` — free-text shown on the receipt
- `receiptHeader1`, `receiptHeader2`, `receiptHeader3: string` — 3 single-line text fields printed at the very top

Add 5 new rows to the POS section in `SettingsView.tsx`: one Toggle (QR on receipt), one text input (merchant number), three text inputs (header lines 1–3). Inputs reuse the existing `.sett-input` / `.sett-row` classes.

## Part B — Receipt renders the new POS-only content

`components/Receipt.tsx` gains optional props:
- `showQr?: boolean` (default `true`)
- `merchantNumber?: string`
- `headerLines?: string[]` (the 3 lines)

Changes:
1. **Header lines** — render `headerLines` (filtered to non-empty) at the very top, above the business icon/name, as a centered mono block. Only shown when at least one line exists.
2. **Merchant number** — render below the business name in the header (e.g. `Merchant: 1234567`) when provided.
3. **QR gating** — wrap the QR block in `{showQr && (...)}` so it can be hidden.
4. **Print HTML** (`handlePrint`) — the print window reads from `ref.current.innerHTML`, so the on-screen preview already drives print. The QR-gating + header lines + merchant number therefore flow through to print automatically. (Confirmed: the print function dumps the live DOM.)

`CheckoutView` and `OrdersView` continue to mount `<Receipt>` without these props → they keep today's behavior (QR shown, no header lines, no merchant number). **Online receipts are untouched.**

## Part C — POS wires the new props + sends `status: completed`

`views/PosView.tsx`:
1. `readPosSettings()` returns the 5 new fields; the `posSettings` state and the `PosSettings` interface grow accordingly.
2. The `<Receipt>` mount (line 599) passes `showQr`, `merchantNumber`, and `headerLines={[header1, header2, header3]}`.
3. **Auto-complete**: `handlePlaceOrder()` adds `status: 'completed'` to `orderPayload` (line 451). POS is a store-owned action, so this is allowed.

## Part D — Server: POS orders are silent + auto-complete allowed

`app/api/orders/route.ts`:
1. **Detect POS** — compute `const isPos = cashierName != null;` (POS is the only path that sends `cashierName`; confirmed in `PosView.tsx:461`). Online checkout never sends it.
2. **Auto-complete for POS** — change the requested-status logic so a POS order (`isPos && supplierId`) sets `requestedStatus = 'completed'` **without** the staff JWT gate. This is the key fix: today the `completed` gate uses `getAuthUser` which doesn't recognize a staff cashier's `x-cashier-token`, so cashiers can't complete orders. Extend the check so a valid cashier actor for that store also passes:
   - Import `getCashierActor` from `lib/cashierAuth`.
   - In the non-`BUYER_SETTABLE_STATUS` branch, allow when `ownsStoreOrAdmin(user, supplierId)` **OR** `cashierActor?.supplierId === supplierId`.
   - For POS orders specifically, default `requestedStatus` to `'completed'` up front (before the gate) so the cashier path completes automatically.
3. **Silent for POS** — change the 3 `notifyNewOrder(...)` call sites (lines 445, 577, 710) to `if (!isPos) notifyNewOrder(...)`. This skips in-app notifications, realtime fan-out, and Web Push for POS sales. Online orders still notify exactly as before.
4. **`isPos` flows into all 3 creation paths** — they share the top of the handler where `cashierName` is parsed, so one `isPos` boolean covers all three (place_order RPC, place_order_v2 RPC, legacy JS).

## Files touched
- `views/SettingsView.tsx` — 5 new POS settings rows + `DEFAULTS`
- `views/PosView.tsx` — `PosSettings` + `readPosSettings` grow; `<Receipt>` gets new props; `handlePlaceOrder` sends `status: 'completed'`
- `components/Receipt.tsx` — 3 new optional props (showQr, merchantNumber, headerLines); render gating
- `lib/receiptSettings.ts` — export a helper to read the new fields (matches existing pattern)
- `app/api/orders/route.ts` — `isPos` boolean; POS auto-completes; cashier allowed to complete; POS skips `notifyNewOrder`

## What stays the same
- Online checkout receipts (QR on, no header lines, no merchant number) — unchanged.
- Online order notifications + `pending` status — unchanged.
- All existing order tests still pass (POS discount, attribution, PII, rules, guards).

## Out of scope
- No DB migration (no `source`/`channel` column needed — `cashier_name IS NOT NULL` already distinguishes POS).
- No per-device sync of receipt settings (settings remain localStorage, matching the existing pattern).

## Result
A cashier rings up a sale → clicks Pay → the order is created **completed** and **silent** (no bell, no push) → the receipt prints with the 3 header lines + merchant number, and the QR shows only if the owner enabled it in Settings.
